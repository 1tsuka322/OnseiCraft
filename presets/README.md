# presets/ —— 公开预设知识包

**为什么有这个目录**：这个项目的效果有很大一部分不在代码里，而在**知识表**——
术语怎么统一、ASR 错字怎么改、什么算表记差异、译文该有什么风格。
没有这些，管线能跑通，但出来的是「机翻感很重的字幕」。

所以这里放**可以公开的那部分**：规则、词典、统计量、语言事实。
不放的是**语料本身**（逐句平行对照、逐句人工修正）——那是从他人作品派生的内容。

## 内容

| 文件 | 作用 | 用它的阶段 | 可替换 |
|---|---|---|---|
| `glossary.json` | 术语 → 固定译法（进 prompt） | 03 初译 | ✅ 建议换成你自己的 |
| `pin_sets.json` | 允许集：同一词的多个可接受译法 | 05 术语锁 | ✅ |
| `asr_errata.json` | ASR 错字 → 正确写法 | 02 改错 | ✅ 边用边加 |
| `do_not_change.json` | 表记差异白名单（**不许**当错字改） | 02 改错 | 一般不用动 |
| `hard_rules.txt` | 硬约束（带统计百分比） | 04 润色 | ✅ 换成目标译者的 |
| `user_rules.txt` | 标点与译法规范（优先级最高） | 03 / 04 | ✅ 按你的偏好改 |
| `stats.json` | 人工风格统计（句长/标点率…） | 06 校验参照 | ✅ |
| `grammar_patterns.json` | 语法模式（句尾三态、语气词映射） | 04 / 06 | 一般不用动 |
| `kana_variants.json` | 假名变体归一 | 02 | 一般不用动 |
| `style_guide.txt` | 风格指南（模型归纳） | 04 | ✅ |
| `parallel.json` | few-shot 例句 | 04 润色 | ✅ **强烈建议换成自己的语料** |

## 这个包是怎么来的

- 规则/词典/统计：从维护者的私有风格库导出；
- `asr_errata.json`：**剔除了带 `works` 作用域的条目**（那些是针对特定作品判定的，别人用不上）；
- `parallel.json`：**不是真实语料**，是 32 条手写合成样例，只演示风格
  （句末句号、少语气词、口语化）。真实语料 17MB 不入库。

## 效果分档（实话）

| 配置 | 效果 | 说明 |
|---|---|---|
| 只有 `presets/` | **能用的及格线** | 术语一致、错字能改、标点规范；润色偏「平」，因为没有目标译者的 few-shot |
| `presets/` + 自己的语料 | **明显更好** | 用 `scripts/style/build_library.py` 从你自己的素材重建 `parallel.json` 与统计 |
| 自己维护的完整知识表 | 最好 | 术语/错字边用边加，这是长期收益最大的一件事 |

## 换成你自己的

```bash
# 方式一：直接改 presets/ 里的表（最简单）
# 方式二：放到别处，用环境变量指过去（推荐，presets/ 保持干净）
export KIKOERU_STYLE=/path/to/my_style

# 从自己的语料重建风格库
python scripts/style/build_library.py <你的语料目录>
```

管线内部顺序：`KIKOERU_STYLE` → `<repo>/.workbuddy/style` → `<repo>/presets`。

## 内容提示

`glossary.json` / `pin_sets.json` 里有本领域的成人词汇（这是词汇事实，不是语料）。
如果你的部署环境不适合出现这些词，删掉对应条目即可——管线会退化成「不做术语统一」，
不会报错。

## 怎么加一条错字

见 [`../docs/KNOWLEDGE.md`](../docs/KNOWLEDGE.md)。要点：**必须带反例**，
只给正例的规则一定会误杀。
