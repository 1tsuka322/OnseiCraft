# presets/ —— 公开预设知识包

**为什么有这个目录**：这个项目的效果有很大一部分不在代码里，而在**知识表**——
术语怎么统一、ASR 错字怎么改、什么算表记差异、译文该有什么风格。
没有这些，管线能跑通，但出来的是「机翻感很重的字幕」。

所以这里放**可以公开的那部分**：规则、词典、统计量、语言事实。
逐句文本（平行对照、人工修正）不随仓库分发。

## 风格模型：语料不能给，但「风格」可以给

`style_guide.txt` 和 `style_model.json` 是从 **87832 句人工译文**里统计出来的，
**不含任何一句原句**。它回答的是「这个译者习惯怎么写」：

- 句长：以 10–14 字为主（32%），超过 25 字的不到 4%
- 标点：每百句约 13 个逗号、14 个省略号、8 个问号
- 虚词密度：的、了、是、我、不、这、一、你
- 句尾形态：吗？、了呢、吧？、了哦
- 句式骨架：`X的X`、`好X`、`X了`、`X吧`、`不X`
- 日语句尾 → 中文常用收尾：疑问 → 了吗/了吧/对吧；终助词 → 了呢/了哦/对吧

这是「给风格不给语料」的做法：**统计事实可以公开，逐句表达不行**。

> ⚠️ 一个刻意的取舍：没有用「中文句末标点」做对应统计。
> 人工字幕是**不带句号的旧时代产物**，统计出来全是「无标点」，
> 写进指南会教模型不写句号，与 `user_rules.txt`（句末句号）冲突。

## 这个包是怎么来的

- 规则/词典/统计：从维护者的私有风格库导出；
- `asr_errata.json`：**剔除了带 `works` 作用域的条目**（那些是针对特定作品判定的，别人用不上）；
- `parallel.json`：**不是真实语料**，是 32 条手写合成样例，只演示风格
  （句末句号、少语气词、口语化）。真实语料不随仓库分发。

## 换成你自己的

```bash
# 方式一：直接改 presets/ 里的表（最简单）
# 方式二：放到别处，用环境变量指过去（推荐，presets/ 保持干净）
export KIKOERU_STYLE=/path/to/my_style

# 从自己的语料重建风格库
python work/scripts/style/build_library.py <你的语料目录>
```

管线内部顺序：`KIKOERU_STYLE` → `<repo>/data/style` → `<repo>/presets`。

## 内容提示

`glossary.json` / `pin_sets.json` 里有本领域的成人词汇（这是词汇事实，不是语料）。
如果你的部署环境不适合出现这些词，删掉对应条目即可——管线会退化成「不做术语统一」，
不会报错。

## 怎么加一条错字

见 [`../docs/KNOWLEDGE.md`](../docs/KNOWLEDGE.md)。要点：**必须带反例**，
只给正例的规则一定会误杀。
