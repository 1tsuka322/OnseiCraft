## v0.1.0-beta.18 — 2026-10-31（P2 存量清洗：判据去伪 + 音译白名单）

上一版把 `lexical` 门禁挂上后拿到三张清单（302 / 326 / 14）。**离线清洗第一轮**发现：

### 1. 音译 326 → 5（−98.5%），两个根因

| 根因 | 表现 | 修法 |
|---|---|---|
| **`jieba.dt.FREQ` 未初始化** | 词典加载前词频**全是 0** → 「不成词」这道闸门形同虚设 | `_jieba()` 里显式 `jieba.initialize()` |

实测 326 条里约 250 条是 `妈妈*`，全是这两条造成的。

另加 `data/style/translit_ok.txt`（专有名词白名单，一行一个）：

### 2. 实词脱落 302 → 40（−87%），最要命的是**逐行判错了**

`pair_ja` 把一整条 ASR 段分给「起点落在这个窗口里的那一行」。可一条 cue 的译文会被
`render_display_lines` 按逗号切成 2 行 —— 第 1 行只承载「啊。」，整段日文却都归了它，
于是**看着像整句丢了，其实下一行就是后半句**。

实测 RJ1530549 `123.08`「啊。」，下一行 `124.98` 就是「我 那个 随时都可以」，一个词没丢。

**改成按 ASR 段聚合**：一个段拥有它时间范围内的**所有**显示行，把这些行的中文拼起来再判。

剩下 40 条里约 22 条是拟声，又补了两条：
- `_is_repetition` 的 `max_unit` 3→5（`グッチュ`×2、`とっぴゅー`×2、`しっこー`×2 都是 4~5 字单元）
- **全假名 + 实词词性只有「名詞」→ 拟声**（unidic 把任何未知片假名都标 `名詞`）。
  ⚠️ 判据是「**只有**名詞」，不是「没有动词形容词」——`だーいつきー` 被切成 `副詞+名詞`，
  用后者会把这条最经典的实词脱落案例一起放掉。

## v0.1.0-beta.17 — 2026-10-31（P2：词汇层审计进 06 门禁）

### 做了什么

新增 `scripts/lexical_audit.py`，挂成 06 的第 11 个门禁 `lexical`（`hard=False`，只出报表）。
它抓的是 `check`/`empty`/`trunc`/`semantic` 四道**全放过**的一类缺陷 —— **词汇层塌陷**：

```
だーいすきー  → 「哒——！」   整行只剩语气，实词全丢
ハイボク      → 「嗨波克」   音译，中文读者看不懂
DS            → 「DS」       2 字母拉丁（check.py 的 LATIN 是 {3,}，漏这一类）
```

四个检测器：`content_drop`（红）/ `ellipsis_only`（黄，单独计数）/ `translit`（黄）/ `latin2`（黄）。

### 判据调了三轮，每轮都是拿全库数字打回去的

| 轮次 | 判据 | 全库命中 | 问题 |
|---|---|---|---|
| v1 | 假名兜底优先 + `partial_ratio≥0.70` + `[A-Za-z]{2}` | 脱落 545 / 音译 **2638** / 拉丁 73 | 音译几乎全是「要是你←yaoshini(0.71)」这类局部巧合；`VIP` 被拆成 `VI` |
| v2 | 音译只看**片假名串**、改整体 `ratio`；拉丁加词边界 + 白名单 | 431 / 542 / 13 | 脱落里拟声句占三分之一（`よっしょ。`→「嘿咻。」被误判） |
| v3 | **fugashi 权威判定**（`感動詞`/`副詞` 不算实词）+ 纯重复 + 短音素单调前置 | **302 / 326 / 14** | 抽样精度约 **54%**（302 条里约 160 条是真的） |

关键顺序（别调回去）：**纯重复 → 短音素单调 → fugashi → 假名兜底**。
`ぎゅぎゅぎゅ` 会被 fugashi 切成 `名詞`，所以重复判定必须在它前面；
`よっしょ`/`むむむ` 必须走 fugashi 的 `感動詞`，所以假名兜底只能在最后。

### ⚠️ 澄清一个误解：改 06 **会**让 03 指纹失效

`stage_fingerprint` 的 payload 里有 `runner`（`pipeline_lib/*.py` 的聚合哈希），
所以**任何** pipeline_lib 改动（加门禁、改 DEFAULTS、改 profiles）都会让 6 个阶段全失效。
本次改完按老办法处理：04/05/06 重跑或按证据 `restamp`，01/02 按证据 `restamp`，
03 因 `code` 闭包含 `polish.py`/`lock_match.py` 走 `--force --why`（03 输出不受影响，
重跑要 1 小时 GPU 且会改全部译文）。**代价是几分钟，不是一小时** —— 但「06 改动不影响 03」
这句话本身是错的，别再按它做排期。

## v0.1.0-beta.16 — 2026-10-31（E1 锁文本锚定 + 覆盖度门禁 + 指纹缓存恒失效）

三件事，都是「声明 ≠ 执行」：**登记的规则没有落地，而日志看不出来**。

### 1. E1 锁改文本锚定（P0）

**问题**：4187 条人工句级锁按 `文件|时间戳` 存。重跑一次切分，时间戳漂 0.3~1.6 秒就静默失效 ——
`apply_lock` 匹配不上就返回原文，日志只写「覆写 N 行」。实测 17 部新路线作品
**1032 条锁只有 547 条落地（53%）**。

**改法**（`lock_match.py` v3 + `polish.py`）：锁不再按显示行匹配，改为**先分给 cue**：
`score = 0.7*sim(锁日文, cue日文) + 0.3*(1-漂移/8s)`，`sim = max(lcs, jaccard)`。
显示行的切分依赖最终译文，写盘前拿不到行清单，而 cue 的 start/end/ja 早就确定了 ——
所以 cue 是唯一稳定的锚点。写盘时再落到该 cue 里**时间最近**的显示行。

三条判据边界（都踩过）：

- **没有日文锚点 → 一律不猜**。曾有「窗口内时间唯一就认它」的兜底，实测把一句不相干的
  中文盖到了错位的锁上（RJ01654115 `[05:51.22]`：锁文说「不能随便把任何东西交给别人」，
  该处 ASR 是 `おまんこおかしくなっちゃう`）。**错位比丢失更坏** —— 丢失会被门禁报出来。
- **漂移 >2s 不认**：短句的 lcs 会被长文本包含而虚高到 1.0，时间项压不住时宁可漏。
- **时间戳精确命中给 1.1 分**（严格高于公式上限）：用 1.0 会和「锁 ts 落在 cue 区间内 +
  文本全同」打平，被 tie 判据误判成歧义，把最强证据丢掉。

### 2. 新增门禁 `locks`（06 第 10 项）

`scripts/lock_coverage.py`：拿成品 LRC 反查每条锁有没有落地。
`landed` / `missing`（有锚点却没落地，**红**）/ `no_anchor`（无日文，**黄**，待人工）/ `unreadable`。
判据用**去标点子串**，不能用整行相等（显示层按逗号拆行，整行相等会报 45% 假阳性）。

配套两处：

- `term_lock.py` 现在**读锁表，锁行整行跳过**。实测它按作品多数票（鸡鸡 70 : 肉棒 4）
  把 polish 刚写进去的锁文又改回去 —— 人工裁定必须优先于统计规律。
- `lock_migrate.py` 只给**已验证对齐**的锁补 `ja`（锁文在成品里，或 ±8s 内某行相似度 ≥0.5），
  否则会把错位的锁填成「看起来完全一致」的假配对。补了 663 条。

**效果**：落地 2460（58.7%）→ **3298（78.7%）**；剔除旧路线 RJ377265 后
真丢失 640 → **109**。剩下 390 条无 ja 的锁**不能自动锚定**，是已知未完成项。

### 3. ⚠️ 阶段指纹缓存恒失效（2026-10-30 引入，今天才发现）

`manifest.begin_stage()` 自己调 `manifest.fingerprint()`（**5 字段旧版**），而
`stages.execute()` 用来比对、`acceptance.py` 用来验收的是 `FP.stage_fingerprint()`
（**9 字段**：多了 config/config_hash/env/models/runner）。两边永远不相等 →

- **缓存命中率恒为 0**，每个阶段每次都重跑（beta.15「全库重跑」实际是被这个 bug 强制的）；
- `acceptance` 的「阶段指纹 = 当前代码」这条声明**永远不可能成立**。

修法：`begin_stage(..., fp=)` 由调用方传入算好的那个值，**只算一次**，从结构上消灭
「两个地方各算一份」。验证：连跑两次同一阶段，第二次输出「缓存命中，跳过」。

### 4. 连带发现：部分作品的成品相对 03 草稿是陈旧的

成品里还留着 R155（2026-10-29 已修）的「同一 cue 两行相同文本」bug，说明这些 run 的
04/05 在 03 重跑后**没有重跑就被 promote 了**。`acceptance` 查不出来 —— 它只比
「成品 == run 05」，两边都是旧的就一致。

重跑 04-06 后全库共改 **986 行**，逐行分类：**932 条锁恢复 + 53 条草稿对齐
（含重复行消失）+ 1 条称谓修复（先生→老师）**，无一条非预期改动。已 promote。

## v0.1.0-beta.15 — 2026-10-30（修 L2 前文为空的覆盖面 bug）

**beta.14 上线后发现的问题**：全库 03 跑完 5 部，`L2 带前文救回` 只命中 **2 行**，
而实验里「已失败行」的救回率是 **6/12**。差了一个数量级。

### 根因：`prev` 经常是空的，L2 被静默跳过

`_rescue_line(ja, prev_ja, prev_zh)` 里有一句 `if prev_ja or prev_zh:` —— 前文为空就不走 L2。
而 `_last_ctx(prev_ctx(i))` 在**波次并行**时经常返回 `("", "")`：

- `WORKERS=3` × `CHUNK=3` → 一波 9 行；
- 本波**首块**的 `prev_ctx` 取 `i-3..i-1`，若这几行同在本波且尚未翻译，
  `results[j]` 还是空 → `prev_ctx` 返回空列表 → `_last_ctx` 返回 `("", "")`。

实测（`tmp/daily/probe_l2_miss.py`，RJ1058739 `くる、くーる、くーる。`）：

| 问法 | 返回 | 判定 |
|---|---|---|
| L1 裸单行 | `Ku、Ku、Ku。` | 判脏（拉丁残留） |
| **L2 带前文**（prev_zh 真实译文） | `来，来，来。` | ✅ 救回 |
| **L2 带前文**（prev_zh=「（略）」） | `来吧，来吧，来吧。` | ✅ 救回 |
| L2 无前文（等价于 prev 空） | 一串 prompt 回吐垃圾 | ❌ |

→ 生产日志里那句 `nolang 未救回：くる、くーる、くーる。 -> Ku、Ku、Ku。`，
就是「L2 根本没执行」的结果，不是「L2 试了但失败」。

### 修法：只给重试阶梯补前文，不动主 prompt

1. `translate_block(block, prev_ctx, prev_raw=None)` —— 新增 `prev_raw=(日, 译)`，
   **只在 `prev_ctx` 拿不到时**给 `_pja/_pzh` 兜底。主 prompt 用的仍是 `prev_ctx`，一字未动
   （前文注入主路径会诱发回吐，beta.14 已实测否掉，不能借这个口子复活）。
2. 块内第 2 行起，L2 的前文直接用**本块上一行**（比块首前文更近、更准）。
3. `still` 补跑段：`prev_ctx` 为空时退化成 `(lines[i-1]["text"], "")`。

### 实测结果（全库 17 部 / 147 轨跑完）

`L2 带前文救回` **17 行**（beta.14 全库只有 2 行）。对照改前基线
（`tmp/_p2_baseline.json`，65 行「成品是「…」但 ASR 有实词」）：

| 项 | 数 |
|---|---|
| 救回 | **19** |
| 仍「…」 | 46（其中多数是纯拟声/纯假名，`_nonlexical` 判拟声、本就不该重试） |

典型救回（都是之前实打实丢掉的台词）：

- `くる、くーる、くーる。` → 来吧，来吧，来吧。（就是 beta.14 日志里那条「未救回」）
- `つまきがんばって` → 小椿加油
- `中はやだよ` → 里面不要啦
- `清水ハトラちゃん役小森アホジでした` → 饰演清水哈特拉的我是小森阿呆吉

⚠️ 但救回 ≠ 译对：19 条里约 10 条是音译或半句（`だーいつきー` → 「哒——！」漏了「好き」；
`鬼ぃレル` → 「鬼雷尔沃哦哦哦哦哦DS」还带了 2 字母拉丁残留）。这些比「…」信息多，
但仍需外部审校。**`_sakura_bad` 抓不到「2 字母拉丁」和「漏译后半句」**，是已知缺口。

### 顺带修掉一个验收口径 bug

`acceptance.py` 用 run 的 config **快照**算指纹，而 `pipeline.py run` 用
`paths.load_config()`（= DEFAULTS + pipeline.json）。beta.13 给 DEFAULTS 加了
`seg_flush_chars`/`chunk` 后，快照里没有这两键 → `config_hash` 按 `None` 算，
与运行时记录的 `=10/3` 永远对不上，17 部 × 6 阶段全部假报「不符」。

修法：① acceptance 改用 `dict(paths.DEFAULTS, **快照)`；② 17 个 run 的快照补齐这两键
（值不变）；③ 全部 6 阶段指纹重打。之后 `acceptance.py` 六类声明全绿。

### 1. 为什么需要（实测，`tmp/daily/exp_ctx_retry.py`）

拿「成品是「…」但 ASR 有实词」的行做对照，三种问法各跑：

| 问法 | 救回 | 说明 |
|---|---|---|
| L1 裸单行（原有 `_sakura_retry_one`） | 3/12 | 无上下文，短句/省略句猜不准 |
| L2 单行 + 【前文】+ 编号协议 | **6/12** | 翻倍 |
| L3 = L2 + temp 0.3 | 6/12 | 温度没用，不加 |

### 2. 但前文是**双刃**，所以只能当第二级

补做「长度 × 有无前文」交叉（13 条健康行，每格 2 次）：

| 样本 | 无前文 | 带前文 |
|---|---|---|
| 已失败行（12 条） | 3/12 | **6/12** |
| 健康行（13 条） | **22/26** | 10/26 |

健康行上带前文**帮倒忙**，失败模式全是 `parse_fail`，集中在**重复句**
